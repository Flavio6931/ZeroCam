# Contexto del Proyecto — ZeroCam

## 1. Descripción y Arquitectura
**ZeroCam (`v1.3.0`)** es una cámara virtual de baja latencia 100% clean-room para **Windows 10 / Windows 11 x64** + **Android 8.0+**, con pipeline de video H.264 hardware Zero-Copy de punta a punta y transporte cifrado `ZeroCam Wire v2`:
- **Android (`android/`):** `Camera2` → Surface-a-Surface hacia `MediaCodec` H.264 HW (`KEY_PRIORITY=0`) → `TcpStreamClient` (`ZeroCam Wire v2`: handshake autenticado de 4 mensajes **ECDH/ECDSA P-256** + sesión **AES-256-GCM** con cola acotada anti-bufferbloat de 4 frames y solicitud IDR ante congestión) por **Cable USB (`127.0.0.1` + `adb reverse`, auto-fija huella `FP` del PC sin PIN)** o **Wi-Fi (discovery UDP `:5001` `ZCAM_DISCOVER_V2` firmado con ECDSA P-256 + PIN de 6 dígitos derivado con PBKDF2-HMAC-SHA256 100k + HKDF-SHA256)**.
- **Windows Host (`windows/app/`):** receptor C++20 Win32 + GDI+ Dark Mode (`ZeroCam.exe`), criptografía nativa Windows CNG/DPAPI (`WireCrypto`), decodificación HW `CLSID_MSH264DecoderMFT` (D3D11VA `NV12`), catch-up de backlog TCP (`skipPublish` vía `FIONREAD`), rotación HW vía `ID3D11VideoProcessor`, filtros GPU + Retrato IA RVM (`512×288` cargado en RAM vía `LearningModel::LoadFromStream`) + Bokeh de disco óptico (`960×540`), ring compartido `NV12` cross-device en `C:\ProgramData\ZeroCam\ipc_ring.bin` (DACL restringida a `SY/BA/LS/IU` + Mandatory Label `Medium`, sin `AC`/`BU`), vista previa bajo demanda (`0.0% GPU 3D` oculta/bandeja) y anfitrión dual (`mfsensorgroup.dll` dinámico en Windows 11 `_System` + DirectShow 32/64-bit en Windows 10).
- **Servidores COM Virtuales (`windows/vcam_source/`, `windows/dshow_source/`):** `ZeroCamSource.dll` (`/MT`, `IMFMediaSourceEx` / `IMFMediaStream2` para Windows 11 `FrameServer.exe`, cero-copy DXGI + espera reactiva de `2 ms` sin tirones) y `ZeroCamDShow64.dll` / `ZeroCamDShow32.dll` (filtro DirectShow clean-room `NV12`+`YUY2` para Windows 10).

- **Protocolo, Criptografía y Shared (`windows/shared/`, `android/.../`):** `ZeroCamProtocol.h` (`ZeroCam Wire v2`, `ZCAM_DISCOVER_V2`, puertos TCP `5000..5010`), `WireCrypto.h/.cpp` (CNG ECDH/ECDSA P-256, PBKDF2/HKDF-SHA256, AES-256-GCM, DPAPI), `ZeroCamIpc.h`, `ZeroCamGuids.h`, `WireProtocol.kt`, `WireCrypto.kt`, `SecurePinStore.kt` (AndroidKeyStore AES-256-GCM).

## 3. Reglas Específicas del Proyecto
- En compilación C++ (`WIN32_LEAN_AND_MEAN` + `NOMINMAX`), cualquier cabecera que incluya `<gdiplus.h>` debe exponer `using std::min; using std::max;` dentro de `namespace Gdiplus` antes del `#include <gdiplus.h>`.
- Mantener `/MT` estático y flags de hardening (`/guard:cf`, `/GS`, `/sdl`, `/GR-`, `/GUARD:CF`, `/CETCOMPAT`, `/DEPENDENTLOADFLAG:0x800`) en `CMakeLists.txt`. `ZEROCAM_ALLOW_IPC_ENV_OVERRIDE` solo debe definirse en targets de prueba (`ZeroCamSourceTest`, `zerocam_selftest`), nunca en `ZeroCam.exe` ni `ZeroCamSource.dll`.
- Al compilar desde shell de agente en Windows, anteponer `C:\Program Files (x86)\Microsoft Visual Studio\Installer` al `PATH` si hace falta para localizar Build Tools / VS.
- Diseño UI alineado con `ZeroCam Tokens` (`#0F1117`, `#171A21`, `#1F242E`, `#262C38`, `#2E3545`, `#2D7DFF`, `#22C55E`, `#EF4444`) y marca v4 (`zerocam.ico`, `ic_launcher_*`, `ic_stat_zerocam`).
- Versionado incremental obligatorio: ante cada modificación o nuevo empaquetado, incrementar la versión (`PATCH`/`MINOR`) en `windows/app/ZeroCam.rc`, `windows/app/MainWindow.cpp`, `android/app/build.gradle.kts` (`versionCode + 1` y `versionName`), `installer/ZeroCam.iss` y `scripts/package_release.ps1`.
